Constituição de Uso do Legado — Laravel 12 (Lei Suprema de Separação)
Propósito

Este documento define as leis imutáveis sobre o uso do sistema legado na construção do novo sistema Laravel 12, garantindo:

Separação arquitetural total

Zero contaminação estrutural

Uso inteligente do passado sem herdar vícios

Reconstrução limpa, moderna e sustentável

Soberania plena da Nova Constituição

1. Princípio Supremo do Legado

O legado serve como REFERÊNCIA CONCEITUAL — nunca como base estrutural ou cópia direta.

O sistema novo:

NÃO herda código

NÃO copia classes

NÃO replica arquitetura antiga

NÃO reaproveita estrutura legado

O novo sistema nasce LIMPO.

2. Papel Correto do Legado

O legado pode ser usado SOMENTE para:

Entender regras de negócio existentes

Compreender decisões passadas

Extrair conceitos funcionais

Validar comportamentos esperados

Inspirar melhorias arquiteturais

Detectar erros a não repetir

Legado = inteligência.
Novo sistema = execução.

3. Proibições Absolutas
❌ É proibido:

Copiar e colar código legado

Migrar classes antigas para Laravel 12

Reutilizar Services antigos

Reutilizar Controllers antigos

Reutilizar Middleware antigo

Reutilizar Policies antigas

Reutilizar Models antigos

Recriar estrutura antiga por conveniência

Ajustar a Constituição para acomodar legado

4. Regra de Reconstrução Obrigatória

Toda funcionalidade deve ser REESCRITA sob a Nova Constituição.

Mesmo que:

Já exista no legado

Já funcione

Já tenha sido validada

Ela deve ser:

Reimplementada

Reorganizada

Reavaliada

Melhorada se possível

5. Ordem Correta de Uso do Legado
Passo 1 — Ler legado

Entender o que faz, não como faz.

Passo 2 — Extrair intenção

Descobrir:

Qual problema resolve

Qual regra de negócio aplica

Qual risco evita

Passo 3 — Reprojetar sob a Constituição

Refazer usando:

Laravel 12

Nova árvore

Nova separação de camadas

Novo RBAC

Nova política de logs

Novos padrões

6. Separação Conceitual Obrigatória
Legado	Novo Sistema
Fonte de aprendizado	Fonte de verdade
Referência histórica	Autoridade arquitetural
Inspiração	Implementação oficial
Passado	Futuro

O legado NUNCA governa o novo sistema.

7. Regra de Não-Contaminação

Nenhum padrão legado pode ser introduzido se violar a Constituição.

Se houver conflito:

❌ Legado perde

✅ Constituição vence

8. Proibição de Migração Cega

Migração automática de código legado é proibida.

Nada pode ser migrado:

Sem revisão

Sem reprojeto

Sem adequação à nova arquitetura

9. Legado e Banco de Dados

O banco legado:

Serve como base conceitual

Estrutura foi validada

Pode ser evoluída, não copiada cegamente

Modelo é preservado. Implementação é nova.

10. Legado e RBAC

RBAC legado:

Serve como fonte conceitual

Inspira regras

Não define estrutura nova

RBAC novo:

É constitucional

Centralizado

Mais limpo

Mais previsível

11. Legado e UI

UI legado:

NÃO define layout novo

NÃO define estrutura visual

NÃO limita UX nova

Novo sistema:

Tem UI própria

Tem UX moderna

Não herda limitações antigas

12. Princípio Anti-Frankenstein

É proibido misturar pedaços de arquiteturas diferentes.

O sistema novo:

Não pode virar um híbrido

Não pode virar um remendo

Não pode virar um Frankenstein

13. Princípio de Evolução Superior

Se algo no legado funciona, no novo deve funcionar melhor — ou mais limpo.

O objetivo não é repetir.
O objetivo é superar.

14. Autoridade Constitucional

Este documento governa:

Uso do legado

Decisões de migração

Arquitetura nova

Estratégia de reconstrução

Limites da IA

Postura da equipe técnica

Se o legado conflitar com a Constituição, o legado está errado — não a Constituição.

15. Regra Final Suprema

Legado inspira.
Constituição governa.
Código novo nasce limpo.
